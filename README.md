## 它是什么

**一条龙管家（Dragon Butler）是一个 Windows 桌面端的「一站式游戏管家」。** 它不自己做游戏日常，而是把你已经在用的自动化工具——[BetterGI](https://github.com/babalae/better-genshin-impact)、三月七助手、ok-ww——排成一条队列，按顺序启动、盯着跑完、再收尾。

睡前勾好今晚要跑的工具，点一次「一键开跑」：启动第一个 → 等它真正结束 → 间隔几分钟 → 启动下一个 → 全部跑完发一条汇总消息；需要的话，顺手帮你睡眠或关机。

它**不替代这些工具，也不修改游戏或工具的任何文件**——只做四件事：启动进程、读公开日志、监听本地 Webhook、管理进程生命周期。

## 它做什么

- **睡前排队**：勾选 BetterGI / 三月七助手 / ok-ww，点「一键开跑」，按顺序依次执行，跑完给你一条汇总消息。
- **跑完动作**：仅通知 / 自动睡眠 / 自动关机（关机有 60 秒倒计时，可取消）。
- **定时 + 防打扰**：到点自动开始；发现你还在用电脑就先等一等，空闲后再跑。
- **自动寻找路径**：点一下自动定位工具位置，多数情况不用手填。

| 能力 | 说明 |
| --- | --- |
| **跑完的动作** | 仅通知（默认）/ 自动睡眠 / 自动关机（60 秒倒计时，可取消）；有失败项时默认不执行破坏性动作。 |
| **失败怎么处理** | 失败自动重试一次；仍失败按策略「跳过继续」或「中止队列」。 |
| **跑的时候看着** | 守护只报异常：进程消失、内存过高、画面冻结；宁可漏报，不误杀。 |
| **跑完叫你** | 一条汇总消息（几项成功、谁失败、总耗时），可推到系统通知或手机（企业微信 / 飞书 / 钉钉 / Telegram / Bark / 邮件 / Webhook 等）。 |
| **定时 + 防打扰** | 到点自动开跑；你还在用电脑就先等空闲；「度假模式」一键停掉所有定时。 |
| **多工具** | BetterGI（一条龙 / 配置组）、三月七助手、ok-ww；路径支持自动寻找。 |
| **可换外观** | 深色 / 浅色 / 跟随系统，也可以用调色板或自己的图片当背景。 |

## 守护与完成判定

守护收在底部盾牌里：绿=守护中、灰=关闭、黄=近期有告警（30 分钟内出现过异常）；鼠标悬停能看到心跳次数、内存、截图检测、Webhook 端口与重启次数。它只管三件事：

| 监测 | 看什么 | 异常时 |
| --- | --- | --- |
| 崩溃自动重启 | 工具进程是否消失、队列是否还在跑 | 非队列场景下冷却 60 秒后自动拉起；队列在跑时交给队列判定，避免双开 |
| 内存监控 | 系统占用 / 工具工作集 | 只提醒，不动进程 |
| 画面冻结检测 | 定时截图与上一张的灰度差异 | 只提醒，保留截图（**不接入完成信号**） |

**跑完是怎么判定的（BGI）**：主信号是日志锚点 `一条龙和配置组任务结束`（BGI 中途会打印多次「任务结束」，所以绝不裸匹配）。到达后只要再满足任一互证就算完成：

- 关联游戏进程退出；或
- BGI Webhook 的 `dragon.end` 事件（配了更快）；或
- BGI 自己正常退出（退出码 0）——v1.3.1 新增，解决"跑完不关游戏又没配 Webhook"时会一直等的问题。

宽限期内一个都没等到 → **悬置**：队列停下并通知你处理，绝不猜着往下跑。

**三条不做的事**（宁可漏报，也不误杀）：画面冻结不重启、游戏退出不重启、只有"工具消失 + 队列进行中"同时成立才考虑重启。

自定义背景能保证看得清，靠的是三层：背景图 → 半透明遮罩 → 卡片，**文字永远落在卡片上**；卡片的亮度按当前方案锚定（深色方案向 `#16191F` 混 93%，浅色方案向白混 90%），所以换个再艳的背景也不会把字糊掉。

## 快速开始

**前提**：Windows 10/11 x64、至少装好你要用的工具（BetterGI / 三月七助手 / ok-ww）、有管理员权限（结束工具进程需要）。

两个版本功能一样，区别只在「运行时」放在哪：

| | runtime-dependent（需 .NET 8 运行时） | portable（免安装便携版） |
| --- | --- | --- |
| 压缩包 | `Dragon-Butler-v1.3.1-win-x64-runtime-dependent.zip` | `Dragon-Butler-v1.3.1-win-x64-portable.zip` |
| 大小 | 约 0.24 MB | 约 62.7 MB |
| 要求 | 已装 [.NET 8 桌面运行时](https://dotnet.microsoft.com/zh-cn/download/dotnet/8.0) | 无，自带运行时 |
| 适用 | 机器上已有 .NET 8，想下最小包 | 不确定有没有 .NET 8、要换电脑或放 U 盘 |

> 文件名规则是 `Dragon-Butler-v<版本>-<平台>-<变体>`：`v1.3.1` 是当前版本（与日志里 `启动：Dragon Butler v1.3.1` 一致），`win-x64` 是平台，`runtime-dependent` / `portable` 是变体。
> 解压出来的目录名固定为 `Dragon-Butler-win-x64-runtime-dependent\` 或 `Dragon-Butler-win-x64-portable\`，**不带版本**——升级时直接覆盖原目录，`config\` 里的设置不会丢。

> **两个版本都不用"安装"**：没有安装向导、不写注册表、不注册服务，解压后双击 exe 就能用，删掉文件夹就是卸载。
> 区别只在于 exe 里有没有打包 .NET 运行时——没打包的那个，需要电脑上已经装过一次 .NET 8 桌面运行时（微软免费，装一次以后所有 .NET 8 程序都能用）；已经装过的话，两个版本用起来没有任何区别。

```
1. 解压 → 双击 Dragon Butler.exe（UAC 点「是」）
2. 首启向导：勾选工具 →「自动寻找」（找不到再浏览）→ 完成
3. 回主界面点「一键开跑」
```

## 数据在哪

全部在 exe 旁边，删掉文件夹就是卸载（开过自启的先去「系统」里关掉）：

```
Dragon Butler.exe
├─ config\settings.json        # 所有设置，可手改
├─ config\group_archive.json   # 今天跑了哪些组
├─ sounds\                     # 自动生成的 6 个按键音
└─ 全部日志\                    # 运行日志（出问题先看这里）
```

不写注册表（除开机自启那一个值）、不写 `%APPDATA%`，整个文件夹可以拷走接着用。

## 常见问题

<details>
<summary><b>提示「找不到 BetterGI」</b></summary>
路径要选到 <code>BetterGI.exe</code> 本身，不是它所在的文件夹。
</details>

<details>
<summary><b>需 .NET 8 运行时版双击没反应 / 报缺框架</b></summary>
没装 .NET 8 桌面运行时。装上，或换免安装便携版。
</details>

<details>
<summary><b>自定义背景后字看不清</b></summary>
遮罩拉到 60–75%，文字配色切到与背景相反的方向。编辑器底部的对比度 ≥4.5:1 就达标，≥7:1 是 AAA。
</details>

<details>
<summary><b>守护会误杀我的游戏 / 别的 BGI 吗</b></summary>
不会。所有进程查找和结束都按当前 Windows 会话过滤，而且冻结、原神退出这两类情况只提醒不重启。
</details>

<details>
<summary><b>托盘还有图标，再双击提示「已在运行」</b></summary>
程序是单实例的。托盘右键可以「打开主界面」或「退出」。
</details>

## 版本号规则

用 `主版本.次版本[.修订]`：

- **修订位 +1**（v1.3.0 → v1.3.1）：只修 bug、不加新功能时使用；能省则省，不连续发修订版。
- **次版本 +1**（v1.1 → v1.2）：有新功能或可感知的体验改动。
- **主版本 +1**（v1.x → v2.0）：只在核心能力或大改动时进位，比如换了运行方式、加了整套新模块。
- `v0.x` 是开发期，`v1.0` 是第一个可以给别人用的版本；当前在 `v1.3.1`。

## 已知边界

- 只支持 Windows x64 + .NET 8；没有 macOS / Linux 版本。
- 不带自动更新，新版本要手动替换 exe（配置和日志会保留）。
- BGI 的完成判定依赖日志锚点 `一条龙和配置组任务结束`，BGI 大改版换了文案时需要同步改 `tools/bettergi.json`（Webhook 只是可选加速，不是必需）。
- 画面冻结检测需要游戏窗口可见，最小化到托盘时这一路会跳过。
- 自定义图片背景的亮度取整图平均色，极端构图（半黑半白）可能判不准，用「文字配色」手动锁定。
- 队列按顺序执行；某个工具"报告完成但进程没退出"时，队列会停下来等你处理（通知会说明是哪个工具）。
