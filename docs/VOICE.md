# 管家说话的方式（VOICE）

这份文件管一件事：**这个软件的界面文案该怎么写。**

它不是风格建议，是验收标准。新写的每一句用户可见的话，都要能对上这里的规则；
对不上的，改文案，不要改这份文件。

---

## 一、灵魂句（逐字，禁改）

下面六句是已经定下来的原话。**一个字都不能动**——标点、空格、破折号都一样。
它们散落在界面各处，任何一次改版只能把它们原样搬过去。

| # | 灵魂句 | 它管的地方 |
|---|--------|-----------|
| 1 | `跑过，但没有留下可说的记录。` | 日志/记录的空态 |
| 2 | `还没攒够时间，跑几天就有数了。` | 时间账的空态 |
| 3 | `现在一个插件都没有。这不影响任何功能——管家自己就能跑完一套。` | 插件页的空态 |
| 4 | `自启的意思是「它就在」，不是「在你脸上开一扇窗」。` | 向导里自启动那一项的副文案 |
| 5 | `挂机时每跑完一个工具就弹一次，比不提醒更烦。` | 通知默认值的解释 |
| 6 | `BetterGI：还没设置路径（可稍后在工具卡里设置）` | 向导总结里的诚实示例，同类句式照这个写 |

关于第 6 句：它不是一个固定字符串，是一种**句式模板**——
`{工具名}：{当前真实状态}（{出口}）`。写别的工具时照这个骨架填，别自由发挥。

## 二、语气规则

1. **口语，克制，像管家说话。**
   是「它在跑」「跑完了」，不是「系统正在执行任务」「任务执行完毕」。

2. **解释默认值必须带「为什么」。**
   只说「默认不推送」是命令；说「默认什么都不弹——挂机时每跑完一个工具就弹一次，比不提醒更烦」才是解释。
   用户改不改是他的事，但他得知道为什么这么定。

3. **空状态先安抚，再给出口。**
   先告诉他「这不是坏了」，再告诉他「你可以去哪」。
   顺序反了就是在催人。

4. **禁堆叠感叹号。** 一个都不必有。
5. **禁营销话术。** 「全新升级」「极致体验」「一站式」——这类词一个都不进界面。
6. **禁生硬 emoji。** 界面正文里不出现 emoji。
   例外：IM 日报的分区头 emoji 按现行推送规范保留（那是给手机小屏幕做视觉锚点的，不是装饰）。

## 三、反例（照着抄会出事的写法）

每一条灵魂句都给三个反面写法。写的时候如果脑子里冒出的是右边这些，停下。

### 灵魂句 1
> `跑过，但没有留下可说的记录。`

- ✗ `暂无数据`
- ✗ `记录为空`
- ✗ `请先运行一次任务以生成日志`

反面写法的共同毛病：把人当成在读数据库报表。第一句是「没有数据」，第二句是「你的记录是空的（你可能做错了什么）」，第三句是在指挥人。
原句说的是：这件事发生过，只是这次没留下话。这是三件不同的事。

### 灵魂句 2
> `还没攒够时间，跑几天就有数了。`

- ✗ `暂无足够数据`
- ✗ `统计数据不足，无法生成`
- ✗ `请先积累至少 3 天的运行记录`

「无法生成」是在宣布一个失败；原句是在说一件正在发生的事——时间还没攒够，攒够自然就有。
注意原句里没有承诺具体几天，别自作聪明加一个数字。

### 灵魂句 3
> `现在一个插件都没有。这不影响任何功能——管家自己就能跑完一套。`

- ✗ `插件列表为空`
- ✗ `请先安装插件`
- ✗ `未检测到插件，部分功能可能受限`

「请先安装插件」是错的：**不装插件什么都不缺**。这一页是「可以往里放东西」，不是「必须先放东西」。
「部分功能可能受限」更是编造——没有这回事。

### 灵魂句 4
> `自启的意思是「它就在」，不是「在你脸上开一扇窗」。`

- ✗ `开机时自动启动本程序`
- ✗ `启用后将随系统启动`
- ✗ `开机自启：开启后可实现无人值守`

这三句都是「说明书」，说的是机制，不是「为什么这事对你划算」。
原句回答的是用户心里真正的问题：「它会不会烦我？」

### 灵魂句 5
> `挂机时每跑完一个工具就弹一次，比不提醒更烦。`

- ✗ `默认关闭通知`
- ✗ `为减少打扰，默认不发送通知`
- ✗ `建议开启通知以获得完整体验`

「默认关闭通知」是命令；「为减少打扰」是官腔；「建议开启」是在跟默认值唱反调。
原句承认了一个具体场景（挂机、一个工具一次），所以它不像规定，像经验。

### 灵魂句 6
> `BetterGI：还没设置路径（可稍后在工具卡里设置）`

- ✗ `BetterGI：未配置`
- ✗ `BetterGI：路径无效`
- ✗ `BetterGI：请设置路径后再继续`

「未配置」是系统语言；「路径无效」是错的（根本还没设，不是设错了）；
「请设置路径后再继续」是在拦人——向导允许你带着没配的项走下去，第 5 步的诚实总结就是为了这个。
原句的结构是：**名字 + 现在的真实状态 + 一个不催人的出口**。

### 标杆句（v1.42 新增，非灵魂句）

> `把 BetterGI 从今晚清单移除？配置会保留，随时可以再加回来。`

- ✗ `确定要删除吗？此操作不可撤销。`
- ✗ `移除后将无法恢复，是否继续？`
- ✗ `该工具将从列表中删除。`

前两句把一个可逆的动作说成不可逆的，人会被吓得不敢点，或者点完之后以为自己毁了什么；
第三句是系统语言，只描述了机器会做什么，没回答「我的设置会不会没了」。

原句的结构是：**做什么（准确到对象名）+ 会保留什么 + 出口在哪**。
这一句是 M8-2 定的，`把 {名字} 从今晚清单移除？配置会保留，随时可以再加回来。`
换工具名时只换中间那个名字，后面两句一个字都别动。

## 四、写新文案时的自查

- [ ] 这句话里的每个事实，代码里都真的会发生？（编造状态是最严重的错）
- [ ] 有没有解释「为什么是这个默认值」？
- [ ] 空态是先安抚还是先指责？
- [ ] 有没有感叹号、营销词、emoji？
- [ ] 专有名词保留英文了吗？（BetterGI、Webhook、API、exe）
- [ ] 这句能不能用更短的句子说完，而不丢信息？
