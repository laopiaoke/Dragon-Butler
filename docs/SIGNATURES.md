# 失败模式签名档案（S1–S15）

> 用途：动代码前逐条自查（生成时）+ 审查/复核报告引用「命中 S#」时的核对基准。
> 维护规则：新增签名必须附本项目已证实案例，纯理论推测不收录。

## S1 UI 有、底层无

设置项/按钮在界面存在，对应执行代码（注册表/系统调用/进程操作）从未实现。

已证实：开机自启开关（UI 存在、注册表 Run 键无写入）。

## S2 有代码、未接线

函数/事件存在且逻辑正确，但从未被调用、Timer 从未 Start、
`Process.EnableRaisingEvents` 未置 true（`Exited` 永不触发的经典变体）。

已证实：定时/走开检查原挂在主窗（`MainWindow` 的 30 秒 Timer）上，功能写对了，
但主窗一关收进托盘就再没人调用它——当晚那一次静默错过（v1.46.0 修复，改挂到 `App` 启动）。

## S3 空壳实现

方法体是 TODO / 空操作 / 只 log 不做事。

## S4 异常吞噬

`catch` 后只写日志不做恢复，故障静默吞掉。

已证实且复发过：M12-4 现场包清理直删失败仍记「已删除」（M12-4b 修复）。

教训：S4 扫描不只扫旧代码，新 diff 同样要过签名。

## S5 状态机死态

某状态进入后无出边（如「运行中」遭遇工具进程死亡后悬空，守护前置条件失效）。

## S6 事件订阅无退订 / 订阅了错误对象

遗留待办：旧通知徽章跨线程问题（v1.45 登记，未修）。

## S7 改了没持久化

界面状态变化后未写入存储，重启回退。

## S8 进程识别错误

进程名/路径与实际不符（外部工具实际进程名以实测为准，如 `BetterGI.exe`）。

## S9 权限链断裂

非提权管家 × 提权工具组合：`Kill` 失败被吞 / 自启后 UAC 卡死 /
manifest 提权级别与自启方式不匹配。

## S10 完成判定误报

日志适配器把未知行误判为完成 → 队列提前推进。

## S11 旧版本迁移缺失

配置 schema 演进时旧字段被静默丢弃。

红线：`SelectedGroups` 的 16 处迁移兼容引用**禁止当死代码删除**（v1.45.1 已确认保留）。

## S12 自身崩溃无自保

无全局异常处理（`AppDomain.UnhandledException` / `DispatcherUnhandledException`），
管家自己挂掉整条链静默消失。

## S13 死胡同提示（v1.45 追认）

提示用户「换个端口再试 / 稍后重试」，但界面上无处可做。

已证实：webhook 端口冲突（任务书 #5 修复）、剪贴板复制失败（#11 修复）。

规矩：错误提示必须带可执行的修复路径。

## S14 假成功留痕（v1.45 追认）

留痕/UI 宣称的状态与实际发生不符（记了「已删除」实际没删、宣称「进回收站」实际没进）。

已证实：M12-4 现场包清理（v1.45 修复）。

补充案例：配置备份导入中途写盘出错、或包里根本没有可恢复文件时，返回值仍是「成功」，
界面照样弹「恢复完成」（v1.46.0 修复：返回值加 `Ok`，失败如实说「没有恢复任何文件」）。

规矩：留痕按实际结果分支记录；UI 宣称不得超出实际能力。


## S15 首帧呈现后才执行隐藏/关闭/状态切换（v1.46.1 追认）

`Show()` 已经把窗口交给合成器，之后才 `Hide()` / 改 `WindowState` / 改 `Visibility`，
中间只要还夹着别的语句，屏幕上就会先亮一帧再消失。用户看到的是「闪一下」，
而代码作者看到的是「我明明 Hide 了」——两者都成立，因为时序被拆成了两拍。

已证实：设置项「启动时最小化到托盘」原在 `OnStartup` 末尾才 `Hide()`，
而 `Show()` 到那行之间还隔着刷红点、播两张报告、建托盘、起调度定时器——
闪帧现象被多次报告，v1.46.1 修复（四个呈现属性全部提前到 `Show()` 之前，
见 `StartupPresentation.PrepareHidden`；恢复显示时再按相反方向还原）。

同族变体：`Loaded` / `ContentRendered` 里做 `Hide()`、把 `Visibility` 从 Hidden 改成 Visible
来「先藏后显」、`WindowState = Minimized` 写在 `Show()` 之后。判定要点只有一个：
**要藏的东西必须在 `Show()` 之前摆好**，`Show()` 之后只允许「已藏好」的确认动作。

规矩：呈现状态（`Visibility` / `WindowState` / `ShowActivated` / `ShowInTaskbar`）
一律在 `Show()` 之前设；`Show()` 之后不做任何「先亮再收」的补救。
源码级断言用切片 + 正则查这个顺序，不查某一行怎么写（见 PATTERNS 第 7 条）。
