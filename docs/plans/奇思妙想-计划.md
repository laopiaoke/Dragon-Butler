# 奇思妙想清单

调研时间：2026-11-17，约 1 小时。工具受限，`web_search` 余额不足不可用、维基与 HN 连不上，全部走 GitHub API + 直接抓网页。

**结论先说**：这个软件真正的独特位置不是「调度游戏脚本」，而是——**它是唯一一个站在游戏外面、整晚都在看、并且知道「正常」长什么样的程序**。下面十条都从这个位置长出来。

---

## 调研到的四个事实

| 事实 | 依据 |
| --- | --- |
| BetterGI 只管「游戏里怎么操作」，不管「跨工具编排、失败后恢复、结果留档」 | 1.8 万星，README 全部是游戏内功能；FAQ 只谈封号与权限 |
| 这条赛道几乎没人。最接近的 `gacha-ops` 只有 2 星，30 个 issue 全是作者自己的提交记录，**没有一条用户反馈** | GitHub API |
| 它的代码值得读：`LogMonitor.cs` 28KB，做断点续读、UTF-8 解码状态跨读保持、长行重叠 512 字符、文件轮转跟随；`RunRecord` 里带 `0xC0000005 → 访问冲突，还需配合事件查看器` 的人话解释 | 逐文件读过 |
| 「环境感知 / 叙事化日志 / 配置漂移检测 / 意图式自动化」这几个词在 GitHub 上搜不到对应项目 | search/repositories 全 0 |

三条设计原则（读来的）：

- **Calm Technology**（Amber Case）：需要最少的注意力；能沟通但不必说话；失败时也要能用；够用就停。
- **Local-first**（Ink & Switch）：没有转圈；数据不锁在一台机器；网络是可选的；Long Now。
- **Home-cooked software**（Robin Sloan）：为四个人写的软件，成功得不能再成功。

---

## 十条

按「越想越有意思」排，不按好做程度排。

### 1. 它自己写复盘

**是什么**　跑完之后不给你一串日志，给你一段话：

> 昨晚 23:04 开跑。日常 18 分钟，比平时快 3 分钟。挖矿到 23:26 卡住了，我等到 23:29 才停手——那会儿你还在打游戏，没敢抢窗口。今天还剩挖矿没跑。

**为什么没人做**　日志是给开发者看的，产品经理不会想到「把日志翻译成人话」也是一件产品功能。所有同类工具都在比谁的日志更全。

**怎么做**　现有件已经够了：`GroupArchive`（每段起止）+ `RunJournal`（每项结果）+ `RunEvidence`（错误行）+ `HarvestLedger`（收益）+ 新加的 `Preflight`（为什么没跑）。缺的只是**把五张表拼成一段话的模板**——纯函数，可断言。

**风险**　低。不改任何行为，只读不写。

---

### 2. 它知道你什么时候不在

**是什么**　不定时间。你合上笔记本去吃饭，它才开始跑；你回来一碰鼠标，它已经在收尾了。设置页那行「每天 08:00」变成「你不在的时候」。

**为什么没人做**　`gacha-ops` 做了半个：`ScheduledDesktopGuard` 检查桌面有没有锁、前台是不是自己，**锁了就拒绝跑**。但没人反过来——**正因为你走了，所以现在跑**。这两个方向差一个世界观。

**怎么做**　`GetLastInputInfo` 拿空闲毫秒，`GetForegroundWindow` + `GetClassName` 判断前台是不是游戏，`WTSQuerySessionInformation` 判会话。现有 `IdleGuard`（5 分钟阈值、15 分钟顺延、2 小时升级）已经是这套逻辑的骨架，只是现在用来**等**，改成用来**触发**。

**风险**　中。判错会半夜突然开游戏。要有「连续 N 次判对才启用」的自证。

---

### 3. 它记得住「正常」长什么样

**是什么**　每个配置组跑多久、内存涨到多少、日志里出现哪些行、哪个工具第几分钟开始慢——都记成一条基线。偏离基线不是报警，是**提前一句话**：

> 挖矿最近三次都比平时慢一半，可能路线有问题。

**为什么没人做**　监控工具都在做「阈值」，没人做「基线」。阈值要人设，基线要自己学——后者更难，但对用户是零成本。而这个软件每晚都在产生基线数据。

**怎么做**　`GroupArchive.MedianMinutes` 已有中位数；扩成「窗口 + 分位数 + 趋势」。判据全在纯函数里，可断言。

**风险**　低。只读历史，只多一段文字。

---

### 4. 每个自动决定都留一句「为什么」

**是什么**　它替你做的每一个决定——等了 15 分钟、跳过了挖矿、重启了一次、没敢关机——都记一条，带原因。任何时候点开「为什么」，看得到当时的判断：

> 23:26 跳过挖矿：上次它卡在传送锚点，你设了「卡住就停手」。
> 23:41 没关机：这一轮有 1 项没跑成，关机条件不满足。

**为什么没人做**　自动化的信任问题一直是「它到底干了什么」，业界答案是「给更详细的日志」——那是给开发者的。**给用户的是理由，不是数据。**

**怎么做**　`SentinelService` 已经在产生每个事件；`RunEvidence` 已经在记原因。缺一张 `Decisions` 表和一个查询窗口。

**风险**　低。纯记录。

---

### 5. 时间银行

**是什么**　不玩游戏的人不知道这些脚本值多少钱。它就记一个数：

> 这个月，它替你跑了 41 小时 12 分钟。

不做排行、不做成就、不做分享按钮——**就是个数字**。

**为什么没人做**　所有工具都想做「游戏化」，但游戏化是在消耗注意力，跟这个软件的定位相反。一个安静的数字反而更重。

**怎么做**　`RunJournal` 已有每项耗时，`GroupArchive` 已有每段时长，加起来就是。

**风险**　极低。

---

### 6. 交接单

**是什么**　你要出门三天，它生成一张单子：

> 这三天我会在每天 08:00 试着跑一次。
> 你需要先确认：① 游戏能自动登录（现在不能，需要你手动点一次）② 磁盘还剩 12G。
> 我做不到的：游戏掉线我没法重登。

**为什么没人做**　因为要承认「我做不到什么」，而产品文档从来不写这个。

**怎么做**　`Preflight` 的十项检查反过来用：现在它答「能不能跑」，交接单答「接下来 N 天会发生什么、哪些我兜不住」。

**风险**　低。

---

### 7. 它会在你回来之前收拾好

**是什么**　你不在的时候它跑完，把游戏关掉、把窗口还原、把桌面恢复到你走时的样子。你回来看到的是走时的桌面，加一句「跑完了」。

**为什么没人做**　大多数工具只关心「任务成功」，不关心「把现场还原」。而用户真正在意的常常是后者——尤其在共用电脑上。

**怎么做**　已经有 `KillCurrent`、`Process.Start`、窗口位置记忆（`MiniBarLeft/Top`）。缺的是「记录进入时的窗口布局，退出时还原」。

**风险**　中。窗口布局恢复容易做错，要能整体放弃。

---

### 8. 它会在你不注意的时候变好

**是什么**　不问、不打扰，自己把能改的改好：把刚失败的那组排到明天后面、把你从没用过的通知渠道关掉、把三个月没跑过的工具从队列里移出去。改完在复盘里说一句。

**为什么没人做**　自动调整 = 自动化在改用户的东西，所有人都怕。但**默认不动、只在明确低风险时才动、且每次都留痕可撤销**，这个组合没人试过。

**怎么做**　`ConfigPresets.Sort`（最近用的在前）已经是雏形。要加的是「改动日志 + 一键撤销」。

**风险**　中高。这是唯一一条真的会改用户配置的，必须默认关。

---

### 9. 它会在你还没问的时候就知道你要问什么

**是什么**　你打开程序，它已经把你最可能想知道的放在最上面：

- 上周三失败过 → 「上周三挖矿卡住了，之后没再出现」
- 这个月比上个月多跑了 6 小时 → 「这个月比上个月多 6 小时」
- 有个工具三周没跑 → 「三月七助手三周没跑过，还要留着吗」

**为什么没人做**　这需要「知道用户会问什么」，通常得靠 AI。但**这个问题在这一行几乎不需要 AI**——答案就那几种，穷举得出来。

**怎么做**　`HomeState` 已经有五态；再加一个「今天有什么不一样的」列表，从现有数据里挑异常。

**风险**　低。

---

### 10. 它最后会变成一个你不再打开的程序

**是什么**　这一条不是功能，是目标。

最好的状态是：装好、跑一次、之后再也没主动打开过，只在它偶尔发一句「昨晚卡了一下，已经处理了」时才想起它存在。

**为什么没人做**　因为产品的成功指标是打开率。但这个软件的成功指标应该是**打开率下降**——打开次数越少，说明它做得越好。

**怎么做**　把这条写进 README，作为衡量标准。每一次做功能都问：这个功能会让用户多打开几次吗？会的话就不做。

**风险**　零，但这决定了上面九条怎么排序。

---

## 建议顺序

按「先验证世界观、再堆功能」排：

1. **它自己写复盘**（1）—— 最便宜、最能看出这套叙事对不对
2. **每个自动决定留一句为什么**（4）—— 给复盘提供素材，也是信任的地基
3. **它记得住正常长什么样**（3）—— 前两条的数据基础
4. **它知道你什么时候不在**（2）—— 第一个真正「没人做过」的交互
5. **时间银行**（5）+ **交接单**（6）+ **它会在你还没问的时候就知道**（9）—— 三条小的，同批做
6. **它会在你回来之前收拾好**（7）—— 有风险，单独一版
7. **它会在你不注意的时候变好**（8）—— 最后做，默认关
8. **它最后会变成一个你不再打开的程序**（10）—— 永远是判断标准，不是功能

前四条做完，这个软件就不再是「BetterGI 的启动器」，而是**一个记得住你作息、说得清自己做过什么的管家**。后半句是它跟所有同类工具唯一的分界线。
