# 第三批候选：从 B 站看玩家到底在关心什么

> **状态更新（2026-11-08）**：你已经选了「开始吧」，本批的 **G1（收益账本）与 G5（补跑进晨报）已经实现并发到 v1.10**；随后的「继续吧」又把 **G3（MCP 接口）**做掉，发到 **v1.11**。
> 实现细节与决策见 [`docs/路线图.md`](路线图.md) 的第十五节（G1/G5）与第十六节（G3）。本文档保留当时的调研原文与判断过程——包括那些**没做**的项（G2/G4）和**当时想错的地方**，它们仍然是下次立项的依据。

> 这份文档**没有立项**，是给你看的候选清单。每一项都标了数据出处、作用、落点、用法、验收方式，以及我自己的推荐度。看完你挑，挑完我再动手。

## 一、这次调研是怎么做的，以及它的边界

**做了什么**：用 B 站搜索（按播放量排序为主，部分按最新）扫了 20 多组关键词，覆盖「工具」「需求」「痛点」「代肝市场」「竞品」四个方向，累计看了两百多条视频的标题、简介、播放量、评论数。另外单独查了唯一一个直接竞品 ABGI（`bcmdy/auto-bgi`）的 README 全文。

**必须说清的边界**：

- **没登录 B 站**，所以 `bili_subtitle`（字幕）和 `bili_comments`（评论区）都拿不到。也就是说，**下面所有结论都只来自标题、简介、播放量、评论数这四个字段**，没有一条来自评论区原话。搜索页二维码一直等不到扫码，这一步缺了。
- **播放量会骗人**。「原神」这个词带进来的泛流量极大，一个搞笑视频能顶十个工具视频。所以我没有按绝对播放量排序，而是**只在「同类内容之间」比较**——比如「BGI 官方发的十几个实机演示里，哪几集播放量最高」，这比「哪个视频播放量最高」有意义得多。
- **「没搜到」不等于「没需求」**。像「原神 日志 报错 看不懂」这种词，搜出来全是搞笑视频，我判断这是「没人做视频谈它」，不是「没人需要它」。
- **代肝市场的数据是价格，不是需求强度**。35r/月起的价格带能说明「有人愿意为省时间付钱」，但说不出这个市场有多大。

## 二、这次翻出来的东西，先说三个「不用做」的

调研的价值有一半在于排除。下面三条我一开始以为有机会，看完数据后判断**不该做**：

| 看起来是缺口 | 为什么不做 |
|---|---|
| **无头 / 黑屏 / 省电挂机** | 玩家的实际解法是**买显示器诱骗器**（`车干不想睡` 1541 播放那条明确写「可以买个显示器诱骗器，黑屏自动挂机，隐私又省电」）。这是硬件层面的解法，软件插手不了。而且我们已经有「夜间息屏」（v1.4 的 `NightScreenEnabled`），软件能做的部分已经做完了。 |
| **CD / 冷却计时** | BGI 官方自己出了「冷却计时器，你的外置大脑来了！」（**54.7 万播放**，是他们播放量第二高的视频），说明这是官方在做的事；ABGI 也已经做了「采集管理」。重复做没有意义。 |
| **配置太多看不懂 → 出教程** | 这是内容需求不是产品需求。`Sleepy Doll`（2.1 万播放）已经证明了「AI 助手帮你读懂配置」这条路，但它是个通用桌面 AI，不是我们能赢的战场。不过它启发了一条**产品化**的路，见下面 G3。 |

## 三、候选清单

### G1 · 收益账本（跑了这么久，到底赚了多少）

> **已实现（v1.10）**：`Dragon Butler/HarvestLedger.cs` + 日志逐行顺手解析 + 队列结束报一句 + 「高级设置 → 收益账本」开关（默认关）。
> 与原文的差别：**没有做「省了多少钱」的换算**——代肝价格是市场行情，会变，而且把爱好换算成钱这件事该由用户自己判断，软件不该替他算。下面保留原文。

**数据出处（这条是全场最硬的）**：BGI 官方播放量最高的十几条实机演示里，**一半以上是「收益播报」体**：

| 视频 | 播放 / 评论 |
|---|---|
| 【实机演示】狗粮+好感+精英+小怪，9.6小时40万摩拉和大量素材 | 132,511 / 847 |
| 【实机演示】AAA狗粮批发72分钟12.5万摩拉 | 97,419 / 656 |
| 【实机演示】锄地2000小怪，8.5小时13万摩拉和海量素材 | 87,630 / 417 |
| 【实机演示】狗粮ABE-A线，40分钟8万狗粮经验或8万摩拉 | 51,549 / 519 |
| 月入1200万摩拉！7.8小时41.5万摩拉！ | 49,541 / 424 |
| 1元=100万摩拉？？？ | 40,538 / 407 |

另外 `回头灬不是岸`（65,614 播放）在简介里直接写「一趟全部跑完大约 10-12 小时，摩拉收益 26-28w」——**玩家自己在口算这个数**。

**这说明什么**：玩家关心「这趟挂机值不值」，官方用视频标题替他回答，但**没有任何工具帮他自己算**。我们能拿到的是同一批日志。

**作用**：每次队列跑完，告诉你这次赚了多少摩拉 / 狗粮经验 / 拾取材料，并累计到日历与周报里。跑满一个月，换算成「按代肝市场价 35–120 元/月，这个月省了多少钱」。

**落点**：
- 新建 `Dragon Butler/HarvestLedger.cs`（纯逻辑，可断言）：`record HarvestRecord(DateTime At, string ToolId, int? Mora, int? Exp, Dictionary<string,int> Materials)`；`Parse(string? line)` 解析 BGI 日志与常见 JS 输出里的收益行；`Ledger` 落盘 `config\harvest.json`，保留 365 天。
- 接线点：`Dragon Butler/QueueService.cs` 的 `FinishQueue`（已有的失败现场包与通知都在这里汇合）。
- 展示：`Dragon Butler/WeeklyReport.cs` 加一句收益汇总；`Dragon Butler/CalendarWindow.xaml.cs` 的格子 `ToolTip` 加当天收益；`Dragon Butler/MiniBarWindow` 空闲时显示本月累计。

**用法**：默认开启（只读日志，不碰游戏）。队列结束的通知里多一句：「本次约 12.5 万摩拉；本月累计 340 万，按代肝价约合 41 元。」

**验收**：`CoordinatorProbe.exe harvest` —— 解析器对六种真实日志行格式的断言；没有收益行时**不写 0 也不报警**（宁可少算，不要算错，同 v1.9 版本检查的原则）；累计与按月聚合的断言。

**风险**：收益数字来自 BGI 日志，格式一变就解析不到。缓解办法是「解析不到就不显示」，而不是显示 0。**绝不猜。**

**推荐度：★★★★★** 证据最硬，落点干净，纯读日志不加依赖，做砸了也只是少显示一个数字。

### G2 · 多账号排队（号 A 跑完自动换号 B）

**数据出处**：两个玩家自己拼的脚本，都不是产品：

- `Miku彡晴天`「[原神]让大肥鱼每天刷两号日常，开机自启动，可随时关停，搭配 bettergi 内启动，完成后有日志汇总」——2,553 播放 / 46 评论，简介写「主要是演示双号切号的，单号太简单了」。
- `Qi-咕咕咕`「原神 全自动每日委托演示 BetterGI 免费代肝」——3,192 播放 / 21 评论，简介写「**基于 bettergi 每天凌晨四点自动开机完成日委，实时上传截图和日志到网盘，自动全程录屏**……后续会收一部分的费用来回一下电费和设备成本」。

同时，代肝市场那边是「40 分钟清完 41 个号」（`-原神星铁代肝阿甘` 2,299 播放）——**一个代肝一天几十个号，全靠人切**。

**这说明什么**：多账号是真实需求，但供给是「自己写脚本」和「人工」。BGI 明确不做（issue #418 一直是 open 的重复标签），ABGI 靠「1Remote 多用户管理」沾了一点边。

**作用**：一条队列里可以放「号 A 的日常 → 号 B 的日常」，每个号用自己的 BGI 配置目录，跑完自动切下一个。

**落点**：
- `Dragon Butler/AppState.cs` 的 `QueueEntry` 加 `public string? AccountId { get; set; }`；新 `AccountRegistry.cs` 管账号（名字 + BGI 配置目录 + 可选备注）。
- `Dragon Butler/QueueService.cs` 的 `RunItemAsync` 启动前切目录；`BuildLaunchArguments` 的 `--startGroups` 保持不变。
- 界面：`Dragon Butler/AccountsWindow.xaml(.cs)`，仿 `GroupsWindow`。

**用法**：设置里登记两个账号，各自指定 BGI 目录；队列里给每一项选账号；照常开跑。

**验收**：`CoordinatorProbe.exe accounts` —— 账号登记/切换目录/切换失败时**停止而不是跑错号**的断言。这条是全项最关键的安全断言：**跑错号的后果比跑不动严重得多**。

**风险**：**高**。切号涉及 BGI 的配置目录语义、可能有登录态、可能触发米哈游的风控（B 站上有一条 22.7 万播放的视频专门讲「自动拾取忘关了不能被封号吧」，说明风险焦虑是真实的）。**我建议这一项先不动，或者只做「手动确认式的排队」——跑完第一个号停下来通知你，你点一下才跑第二个。**

**推荐度：★★☆☆☆** 需求真实但没有一个人验证过「自动切号不封号」，我不认为应该拿你的号去试。

### G3 · 让 AI 能直接指挥它（MCP / 自然语言）

**数据出处**：这条是「反着看」看出来的。B 站上近期有一批**用自然语言驱动 BGI** 的尝试：

| 视频 | 播放 | 做法 |
|---|---|---|
| AI远程清理原神日常，一镜到底 | 25.3 万 | CoPAW + AutoHotKey + BetterGI（明确写「非教程、不构成使用建议」） |
| 【教程】大团长要来了没材料？我让 AI 替我采集钩钩果！ | 32,118 / 176 | 把 BetterGI 丢给阿里 CoPaw，Miniconda 一路装下来 |
| BetterGI软件配置太多？我做了一个 AI 工具帮你放空大脑！Sleepy Doll | 21,098 / 153 | 通用桌面 AI 助手，对话调用工具软件 |

**这说明什么**：**已经有人在做了，而且都是一次性的野路子**——装 Miniconda、配 AutoHotKey、看运气。没有一条是「工具自己就把门开好」。而我们**已经有** `/api/status`、`/api/start`、`/api/stop`、`/api/run`（v1.7 的控制 API），只差一层标准的接口描述。

**作用**：让 Claude / ChatGPT / 你自己的 agent 直接读到「这个软件能干什么、怎么调」，然后一句话让它跑队列、报状态、抓一张图。不用装 Miniconda，不用 AutoHotKey。

**落点**：
- 新建 `Dragon Butler/McpServer.cs`：**不引任何包**，手写一个最小的 MCP over HTTP（`POST /mcp`，JSON-RPC 2.0，只实现 `initialize` / `tools/list` / `tools/call` 三个方法），工具清单直接映射到已有的四个 API 动作，鉴权复用 `ControlApi` 的 32 位令牌。
- 接线点：`Dragon Butler/WebhookHub.cs:HandleRoute` 加一个 `/mcp` 分支（**不新增监听器**，守住 `WebhookHub.cs:10` 那条铁律）。
- 附带产出 `mcp.json` 示例，贴进 README。

**用法**：设置里打开控制 API，把 `http://127.0.0.1:18235/mcp` 和令牌填进 AI 客户端，然后说「帮我看看今天还剩哪几项没跑」。

**验收**：`CoordinatorProbe.exe mcp` —— JSON-RPC 的 `initialize` 握手、`tools/list` 返回四个工具、`tools/call` 路由、令牌校验、**非法请求返回 JSON-RPC 错误而不是 500** 的断言。

**风险**：低。接口面很小，默认关闭，关着时连存在都不暴露（沿用 v1.7 的 404 策略）。

**推荐度：★★★★☆** 代码量小、复用现成件、正好卡在「有人在做但都很糙」的窗口上。唯一的疑问是**你现在没有用户，做了也没人连**——这点你自己判断。

**→ 已实现（v1.11）**：实际做出来比计划多了一项——`initialize` / `tools/list` / `tools/call` 之外还加了 `ping`。另外有两处和原计划不同，都是写的时候才想清楚的：

1. **`WebhookListener.Route` 的委托签名加了第四个参数（请求体）**。MCP 是 `POST` + JSON-RPC，原先是只有 path/query/token 三个参数的 `Func`，拿不到 body 就没法解析。改签名比再开一个监听器代价小得多——那条「全库只有一个文件 `new HttpListener`」的断言到现在还在管着。
2. **`HandleRoute` 里 `/mcp` 分支放在控制 API 之前**。不是因为顺序敏感，而是因为 `ControlApi.Plan` 对非 `/api` 前缀一律返回 404，`/mcp` 得先被认领。

`mcp.json` 示例没有单独出文件，直接写进了 README 的「接到 AI 助手（MCP）」一节——放仓库根上反而容易被误当成「必须放进某个目录」。

**数据出处**：B 站上「BGI 配置」类教程的播放量高得离谱，而且全是**长视频**：

| 视频 | 播放 / 评论 | 时长 |
|---|---|---|
| betterGI锄地的参数配置说明 | 43,311 / 504 | **20:05** |
| 【BGI教程】圣遗物狗粮批发联机配置教程110分钟17~18万狗粮经验附带个人设置截图 | 39,814 / 240 | **146:14** |
| 【BGI教程】原神BGI每日自动拾取狗粮（AAA狗粮批发）脚本使用配置教程 | 27,290 / 177 | **31:05** |
| 【BGI教程】原神材料自动采集与CD效率管理配置教程(BetterGI+autoBGI) | 17,668 / 191 | **21:06** |

**这说明什么**：配置的复杂度已经到了「需要两小时四十分钟视频来讲」的程度。而传播方式是**截图 + 口述 + 网盘链接**——最原始的那种。

**作用**：把「队列 + 依赖 + 配置组切片 + 每个工具的参数」打包成一个 `.dbpack`（就是个 zip + 一个 json），发给朋友双击就能用。反过来也能导出成一份可读的 markdown，贴到群里。

**落点**：新建 `Dragon Butler/ProfileBundle.cs`（纯逻辑：`Export(path)` / `Import(path, bool merge)` / `Describe()`）+ 设置里两个按钮。**不联网、不做市场**——只做文件。

**用法**：「导出编排」→ 得到一个文件；发给朋友；他「导入编排」→ 队列、依赖、切片全部就位。

**验收**：`CoordinatorProbe.exe bundle2` —— 导出再导入后**逐字段等价**（含依赖与切片）；导入别人的包时**不覆盖本机工具路径**（路径是本机的，包里的路径一律丢弃）；版本不兼容时拒绝而不是半导入。

**风险**：低。唯一要小心的是「导入别人的包会不会把本机配置搞坏」——所以默认「合并」而不是「替换」，且**永远不导入可执行文件路径**。

**推荐度：★★★☆☆** 需求证据强（长视频本身就是证据），但**它解决的问题是「分享」，而你现在没有可以分享的对象**。属于「等有第二个用户了再做」的项。

### G5 · 计划点的「没跑成就补跑一次」

> **已实现（v1.10）**：`Dragon Butler/MorningReport.cs` 新增 `CatchUpNote()`，晨报里会多一句「昨天 08:00 的定时没跑成（补跑窗口 120 分钟内没跑起来）」。下面保留原文。

坦白说这条**已经做了**——v1.6 的 F1 定时补跑窗口就在解决它。我把它列出来是因为调研里又撞见了同类痛点：`Qi-咕咕咕` 那条视频的做法是「每天凌晨四点自动开机」，靠**硬件保证**不错过。我们现在是「开机后 2 小时内补跑」，更省事，但只在开机的前提下成立。

**唯一还能做的增量**：把「错过太久（超过补跑窗口）导致今天没跑」这件事，从「静默跳过」变成**第二天早上的一条明确提醒**——「昨天没跑成，因为 08:00 的计划点在 10:00 才开机」。这个我们现在的 `SchedulePlanner.Decide` 已经算得出 `Reason`，只是没在晨报里讲。

**落点**：`Dragon Butler/MorningReport.cs:49 BuildSummary` 加一句；`Dragon Butler/SchedulePlanner` 无需改动。

**推荐度：★★★☆☆** 大概二十行代码，属于「顺手」。

## 四、我的排序建议

如果只做一件：**G1 收益账本**。理由不是它最有想象力，而是**它的证据最硬**——BGI 官方播放量最高的那批视频有一半在报收益，等于替我们做了需求验证；而且它只读日志、不加依赖、做砸了不影响任何现有功能。

**如果做两件**：**G1 + G3**。一个「让玩家看见价值」，一个「让 AI 能指挥它」，两者都不碰执行层，都能写进 CI 断言。

> **事后回看（2026-11-08）**：你选了 G1 + G5，没选 G3。现在看这个选择更对——G3（MCP）的前提是「有 AI 客户端来接」，而本项目还没有那种用户；G5 虽然只有二十行，却是**唯一一个解决「静默失败」的项**，而静默失败正是这类软件最伤人的地方（用户第二天看到「上次执行：两天前」，不知道是没跑还是跑挂了）。

**G2 多账号我建议先别做**——不是技术上做不了，是**没有任何人验证过自动切号不封号**，而你的号是真号。要做也应该先做「跑完停下等你确认」的半自动版。

**G4 配置包**是好东西，但它解决的是「分享」，等有第二个人用的时候再做才不浪费。

## 五、还有一件事得说

调研过程中我确认了一个不太舒服的事实：**ABGI 已经把「网页控制台 + 截图推送 + 定时任务 + 日志关键词编排 + 采集 CD + OBS 录屏 + MCP 接口」做得比我们全**，而且它也有 MCP（`http://ip:端口/mcp/sse`）。

也就是说 **G3 不是蓝海**——ABGI 已经有 MCP 了。但仍然值得做，理由是：ABGI 是网页控制台（要开浏览器）、Vue + AGPL、3 个 star；我们是原生 WPF、MIT、零依赖。**同一个能力，装在你桌面上和开在浏览器里，是两种东西。**

其余几项（DAG 依赖、配置组按项切片、失败现场包、日历热力图、命令面板、任务栏进度、迷你浮条）ABGI 都没有——这些是 v1.6–v1.9 已经建立起来的差异化，不用重复担心。
